# Proofs

Evidence behind [`docs/EVALUATION.md`](../EVALUATION.md). Generated 2026-09-03.
Everything here is output from the scripts in `experiments/` -- nothing is
illustrative or reconstructed.

## Provenance of the audio

All source audio is real production output: twelve generations pulled from the
S3 bucket `dnl-core-sounds-s3-prod` (one user prefix, the `C1` take of twelve
different generations), read under the pre-approved read/download scope for
QA and regression analysis. Format as stored: 32 kHz, 16-bit PCM, stereo,
exactly 8.000 s.

No audio here was generated by a DeepGEN checkpoint, because none exists. Any
future write-up must say the same.

## `audio/`

The listening evidence for `experiments/run_loss_inversion.py`. Four real
clips, four files each, 2.5 s excerpts at the source 32 kHz:

| Suffix | What it is |
|---|---|
| `__1_target.wav` | The real production generation, unmodified |
| `__2_damaged.wav` | Same clip, dulled 12 dB above 8 kHz and collapsed to mono |
| `__3_legacy.wav` | The damaged clip optimised back toward the target under `MultiResolutionSTFTLoss`, 800 Adam steps |
| `__3_perceptual.wav` | The same optimisation under `PerceptualSampleLoss` |

Listen in that order. The two recovered files started from identical audio and
ran an identical optimisation; the only difference between them is the
objective.

`gen01` is the clearest: under the legacy loss the air band ends up **+42.6 dB
hotter than the target** -- the loss injects high-frequency noise that was never
there -- while under the new loss it lands at 0.0 dB and SI-SDR reaches 67.8 dB.

**What this is not.** No network is involved. This isolates the objective
perfectly, which is the point, but it is not a trained model and says nothing
about how a trained DeepGEN would sound.
